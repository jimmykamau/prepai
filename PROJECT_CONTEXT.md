# PrepAI — Project Context

## What we are building

A one-page web tool that accepts a **job title** and returns **three thoughtful, role-specific interview questions** generated by an LLM. The flagship example is "Customer Success Manager".

Audience: hiring managers, recruiters, and candidates prepping for an interview who want a fast starting point rather than generic question lists. Scope is intentionally narrow for a prototype.

## Key decisions

| Decision | Choice | Reason |
|-|-|-|
| Framework | Next.js 16 (App Router, TypeScript) | First-class Vercel target; gives us a server route to hide the OpenRouter key without standing up a separate backend |
| Styling | Tailwind v4 (CSS-based `@theme`) | Matches the Stitch design tokens cleanly with no separate config file |
| Fonts | Geist (display) + Inter (body), via `next/font/google` | Mirrors the Stitch "Cognitive Professional" spec |
| LLM access | OpenRouter (default) or Google AI Studio, both via AI SDK v6 | `AI_PROVIDER` env var picks the provider; OpenRouter for breadth, Google direct for AI Studio's free Gemini tier |
| Default model | `anthropic/claude-sonnet-4.5` (OpenRouter) · `gemini-2.5-flash` (Google) | Best instruction-following for short structured output; overridable via `OPENROUTER_MODEL` / `GOOGLE_MODEL` |
| Structured output | `generateObject` + zod schema (3-element tuple of question/category/rationale) | Removes parsing risk; either we get a valid payload or we 502 |
| Bot protection | Cloudflare Turnstile, env-gated | Real shield on prod, zero friction locally — widget and verification are both skipped when their respective keys are unset |
| Hosting | Vercel | User preference; Fluid Compute runs the route on Node 24 by default |

## Design system

- Source: Stitch project [`5645027595053377922`](https://stitch.withgoogle.com/projects/5645027595053377922) — "Cognitive Professional" theme.
- Two mockups exist: a landing page (form) and a results page (3 question cards).
- Palette anchored on Deep Slate (`#0f172a`) text, Slate-50 background, Indigo (`#4f46e5`) for primary actions, Emerald (`#10b981`) sparingly for success/AI accents.
- Strict 8px spacing grid; 8px radius on small UI, 16px on containers, full-pill on chips.
- "AI Feedback Block" treatment = subtle indigo→emerald gradient hairline border on cards that contain AI-generated content. Implemented as `.ai-card[data-ai="true"]` in `app/globals.css`.

## What is intentionally not in the MVP

- Persistence / question history.
- Sign-in or per-user limits beyond Turnstile.
- Streaming output (we wait for the full payload — the JSON is small).
- Rate limiting at the API route (relying on Turnstile + Vercel platform protections for the prototype).
- Mobile-specific layouts beyond what Tailwind responsive utilities give us.

## How to run

1. `cp .env.example .env.local`, fill in `OPENROUTER_API_KEY` (skip Turnstile for local dev).
2. `npm run dev` → http://localhost:3000.
3. Type "Customer Success Manager" (or use the inline example button) → expect 3 cards in a few seconds.
4. To exercise the Turnstile path locally, add the always-passes test keys: `NEXT_PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA` and `TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA`.

## Deploy

```
npm i -g vercel              # CLI is not installed by default
vercel link                  # link to the Vercel project
vercel env add OPENROUTER_API_KEY production
vercel env add NEXT_PUBLIC_TURNSTILE_SITE_KEY production
vercel env add TURNSTILE_SECRET_KEY production
vercel --prod
```
